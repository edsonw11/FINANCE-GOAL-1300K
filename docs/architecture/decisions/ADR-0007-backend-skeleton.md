# ADR-0007 · Backend skeleton (Phase 2)

Status: Accepted (2026-11-24). Applies ADR-0001 and ADR-0004.

## Decisions
- **`backend/` is its own package** (own lockfile, strict TypeScript, Prettier-free like ADR-0005 for old code but strict for new code). The browser app and its tests are untouched.
- **PostgreSQL 18.7 (alpine), pinned by version.** 18 and not 19: it is the newest major that managed services (RDS) offer today, and it gives `uuidv7()`, so ids are time-ordered (compact indexes) and generated by the database.
- **Prisma 7.10.1 (stable), not 8.0 RC.** A release candidate is not a base for a paid product. Connection through `@prisma/adapter-pg`; the client connects on first use, so the API can start before the database.
- **Vitest 4.1.12, not 5.** Vitest 5 requires Node 22.12+; the project, CI and this machine run Node 20. Revisit when the Node baseline moves.
- **`overrides: effect 3.22.5`.** The Prisma CLI depends on `effect@3.20.0`, which has a high ReDoS advisory (fixed in 3.22.1+). The suggested fix (`audit fix --force`) would downgrade Prisma to 6.x, so one transitive package is raised instead. It is a development-time CLI dependency; the override can be removed when Prisma updates it. `npm audit --audit-level=high` is part of CI.
- **Configuration is validated at startup** (zod), reports all problems at once, **never repeats a received value** (the database URL has a password), and in production refuses the local development password (also when percent-encoded).
- **Health is two endpoints:** `/health/live` (process only, never touches dependencies, so a database outage does not make the orchestrator restart the API) and `/health/ready` (every check with a time limit, 503 with a per-check summary and no error text; the reason goes to the log).
- **Shutdown is explicit** (`src/shutdown.ts`): SIGTERM/SIGINT close the app, exit 0; failure, timeout (10 s) or a second signal exit 1. Nest's `enableShutdownHooks` was dropped: it ends the process by re-sending the signal (no exit code, no time limit).
- **Proxy headers are not trusted** (`trustProxy: false`) and bodies are limited to 1 MiB, both tested by behaviour.
- **Container:** non-root, read-only filesystem, all capabilities dropped, ports bound to 127.0.0.1, healthcheck. Migrations run as a separate one-shot service, not at API start.
- **First table: `app_user`** (id, created_at): the owner every other row will point to. Identity columns arrive with the login phase as their own migration.

## Not done yet (by design)
Authentication and ownership checks (Phase 3), request logging with ids, security headers and CSP (Phase 7), a restricted database role for the API (Phase 7), the domain behind the API (Phase 4).

## Consequences
+ `docker compose up` gives database, migrations and a healthy API; CI runs the same against a real PostgreSQL.
− Two lockfiles to keep audited (root and `backend/`); both are checked in CI.
