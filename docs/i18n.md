# Internationalization (pt-BR, en-US, es)

Decisions (owner, 2026-11-27): currency stays R$ (only the number format follows the language); default category names are translated for display only and stay stored in Portuguese; the quick-entry sentence parser stays Portuguese-only for now; variants are US English and neutral Spanish; a device language the app does not have falls back to English.

Layout (one responsibility per file):
- `src/core/locale-resolve.js`: supported locales, device tag matching, "auto" resolution.
- `src/core/locale-pt-BR.js`, `locale-en-US.js`, `locale-es.js`: one catalog per language (same keys; plural entries `{one,other}`; placeholders `{name}`).
- `src/core/translate.js`: pure lookup, plural and placeholders. `src/core/i18n.js`: active language and `t()`.
- `src/core/language-preference.js`: the saved choice (device setting, not in backup or sync).
- `src/ui/dom-i18n.js`: `data-i18n*` attributes and `<html lang>`. `src/ui/views/language-settings.js`: the card in Ajustes.

Adding a text: add the key to all three catalogs (`tests/unit/i18n-catalogs.test.js` fails otherwise), use `t('key')` in code or `data-i18n="key"` in `index.html`.

Phases: 0 infrastructure and switch (done); 1 navigation and settings; 2 summary and transactions; 3 import; 4 card, investments, categories; 5 domain messages and the printed report.
